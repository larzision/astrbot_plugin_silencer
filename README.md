# 勿扰zzz插件 💤

集成黑名单拦截与睡眠模式管理的多功能插件，由miko倾情打造～

---

## 📖 简介

本插件提供两大核心功能：

1. **黑名单**：拉黑指定用户，阻止其消息触发LLM回复，支持定时自动解除
2. **睡眠模式**：让bot进入勿扰状态，期间消息被缓存，唤醒后恢复为事件重新提交给LLM处理

---

## ⚙️ 工作原理

### 黑名单机制
- 通过 `@filter.on_llm_request()` 钩子在LLM处理前拦截消息
- 检查消息发送者是否在黑名单中，是则终止事件传播
- 定时拉黑通过独立文件 (`expiry.json`) 存储过期时间，每次消息事件时检查清理

### 睡眠模式机制
- 调用 `go_to_sleep` 工具后设置睡眠状态，创建异步定时任务
- 睡眠期间所有非白名单用户的消息被拦截并缓存在 `sleep_cache.json`
- 缓存按会话(对话)独立存储，每个会话最多可配缓存上限
- 唤醒方式有五种：
  - **定时任务**：到点自动执行 `_execute_wake()` 
  - **wake指令**：用户发送"wake"触发唤醒
  - **后台守护**：每3秒检测配置变更，自动处理
- 唤醒时读取缓存，构建 `AstrBotMessage` 对象，通过 `platform.create_event()` + `commit_event()` 创建新事件提交到事件队列，走完整LLM处理流程
- 同时注入【刚睡醒】状态到系统提示中

### 事件恢复机制
- 唤醒时创建的事件使用与被拦截消息相同的 `sender_id`、`sender_name`、`self_id` 和 `session_id`
- 事件通过 `EventBus` 分发，经过所有插件钩子后到达LLM

---

## ⚠️ 平台限制

- **send_message 不适用**：唤醒时通过创建事件而非发送消息，确保走完整处理链
- **pre-config 测试模式**：在 `pre-config` 平台下功能正常，但需要真实平台（如 aiocqhttp/NapCat）才能完全发挥
- **消息缓存**：缓存基于文件存储，重启后不会丢失
- **定时任务**：基于 `asyncio.create_task`，插件重载后自动恢复

## 🚫 黑名单功能

- 拦截指定用户的消息，阻止LLM回复
- 支持定时拉黑，到点自动放行
- 免疫名单：部分用户即使被拉黑也不拦截
- 动态管理：通过LLM工具或命令实时添加/移除黑名单
- 命令权限：管理员 + 命令白名单

## 🌙 睡眠模式功能

- 进入勿扰状态后不回复任何人（白名单除外）
- 支持两种作用范围：全局所有对话 / 仅触发对话
- 睡眠时长可手动指定或使用配置区间随机
- 按对话独立缓存消息，唤醒后恢复为事件发送给LLM
- 唤醒时注入【刚睡醒】状态提示
- 支持白名单，白名单用户不受睡眠影响

## 唤醒方式

| 方式 | 说明 | 处理范围 | 权限 |
|------|------|----------|------|
| 定时任务 | asyncio定时器到点自动唤醒 | 触发睡眠的会话 | 无 |
| wake指令 | 发送"wake"触发check_blacklist | 当前会话 | 管理员+wake_whitelist |
| 手动清状态 | 配置界面关闭睡眠状态 | 自动处理对应会话 | 配置操作 |
| 后台守护 | 每3秒对比配置快照检测变更 | 被移除的会话 | 无 |
| scope变更 | 切换作用范围时清空所有 | 全部清空 | 无 |

## 定时任务

- 每个会话独立 `asyncio.create_task`，互不覆盖
- 使用 `_wake_tasks` 列表管理，自动清理已完成的旧任务
- 插件重载后通过 `_restore_timers()` 从配置恢复未完成的任务
- 手动关闭睡眠时 `_cancel_all_tasks()` 取消所有任务

## LLM工具

| 工具名 | 说明 | 权限 |
|--------|------|------|
| `block_user` | 拉黑用户，主动拉黑违规者 | 管理员 |
| `unblock_user` | 取消拉黑 | 管理员 |
| `go_to_sleep` | 进入勿扰模式，可选时长 | 管理员或配置开放 |

## 命令

| 命令 | 说明 | 权限 |
|------|------|------|
| `拉黑 <ID/@某人> [分钟]` | 拉黑用户，支持@和数字ID | 管理员+命令白名单 |
| `取消拉黑 <ID/@某人>` | 取消拉黑 | 管理员+命令白名单 |
| `黑名单` | 查看黑名单及剩余时间 | 所有人 |
| `wake` | 唤醒bot（睡眠模式下） | 管理员+wake_whitelist |

## 📦 配置项

### 🛡️ 黑名单
- `blacklist` - 黑名单用户ID列表
- `blacklist_enabled` - 启用黑名单
- `admin_only` - 拉黑工具限管理员
- `cmd_whitelist` - 命令白名单（可用拉黑命令的用户）
- `immune_list` - 免疫名单（黑名单免疫）
- `min_block_minutes` - 最短拉黑时长
- `max_block_minutes` - 最长拉黑时长

### 😴 睡眠模式
- `sleep_mode_enabled` - 启用睡眠模式
- `sleep_scope` - 睡眠作用范围（全局/仅触发对话）
- `sleep_mode` - 全局睡眠状态（工具控制，勿手动）
- `sleep_mode_sessions` - 会话级睡眠状态（工具控制，勿手动）
- `sleep_until` - 自动唤醒队列（仅供查看）
- `sleep_whitelist` - 睡眠白名单
- `sleep_disabled_sessions` - 关闭睡眠的对话
- `sleep_max_cache` - 每会话缓存上限
- `sleep_max_total` - 总会话总缓存数
- `sleep_start_time` - 可睡眠时段开始
- `sleep_end_time` - 可睡眠时段结束
- `sleep_duration_min` - 最短睡眠时长（时）
- `sleep_duration_max` - 最长睡眠时长（时）
- `sleep_custom_users` - 可指定时长用户
- `sleep_public` - 睡眠工具开放所有人
- `wake_whitelist` - 唤醒白名单（非管理员发wake的权限）
- `wake_inject_pos` - 刚睡醒注入位置

### ⚡ 高峰期静默
- `peak_hours_enabled` - 启用高峰期自动静默（应对DeepSeek峰谷定价）
  - 开启后每日 `9:00` 自动睡眠180分钟至 `12:00`
  - 每日 `14:00` 自动睡眠240分钟至 `18:00`
  - 强制全局睡眠，不受sleep_scope影响
  - 插件启动时如果在高峰期内也会自动触发

## 缓存回放机制

唤醒时缓存消息按以下策略恢复为事件提交给LLM：
- **私聊消息**：同一会话所有缓存合并为一条事件
- **群聊消息**：同一会话+同一sender的消息合并为一条事件
- 群聊事件自动补全 `group` 信息和 `is_at_or_wake_command=True`，确保LLM正常处理
- 通过 `commit_event` 提交事件队列，走完整LLM处理链，非直接发送消息
